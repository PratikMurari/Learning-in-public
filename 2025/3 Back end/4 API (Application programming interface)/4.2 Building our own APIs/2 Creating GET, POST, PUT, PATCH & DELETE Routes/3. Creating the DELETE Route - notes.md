# Lecture 4: Creating the DELETE Route

## Overview

This lecture focuses on **deleting data** from a RESTful API using:

- `DELETE` requests
- Path parameters
- Basic API key–style authentication

Two delete scenarios are implemented:

1. Deleting a **single joke**
2. Deleting **all jokes** (protected with a master key)

---

## DELETE Single Joke

### Endpoint
```
DELETE /jokes/:id
```

### Purpose
- Deletes one joke matching the provided `id`

---

### Request Data
- Path parameter:
  - `id` – identifies the joke to delete

Example:
```
DELETE /jokes/7
```

---

### Implementation Logic
1. Use `app.delete()` from Express
2. Retrieve `id` from `req.params.id`
3. Convert to integer (recommended)
4. Find the joke index using `findIndex()`
5. If the joke exists:
   - Remove it using `splice()`
   - Send HTTP status `200`
6. If not found:
   - Send HTTP status `404` with an error message

---

### JavaScript Methods Used
- `findIndex()` – locates the index of the joke
- `splice(index, 1)` – removes one element from the array

---

### Notes
- No authentication is required for deleting a single joke
- Designed for simple, low-risk delete operations

---

## DELETE All Jokes (Protected Route)

### Endpoint
```
DELETE /all
```

### Purpose
- Deletes **every joke** in the API
- Simulates a dangerous or admin-only operation

---

### Why Authentication Is Needed
- Deleting all data is highly destructive
- Requires special authorization (master key)

---

### Authentication Method
- Simple API key–style authentication
- Uses a query parameter:
```
/all?key=MASTER_KEY
````

---

### Master Key
- Stored server-side as:
```js
const masterKey = "your-secret-key";
````

- Compared against the key provided by the user

---

### Implementation Logic

1. Retrieve the user key from `req.query.key`
2. Compare `userKey` to `masterKey`
3. If they match:
   - Reset the jokes array to an empty array
   - Send HTTP status `200`

4. If they do not match:
   - Send HTTP status `404`
   - Return “Not authorized” error message

---

### Notes on Authentication

- This is a **simplified** authentication approach
- Used for learning purposes only
- Real-world APIs use:
  - Hashed passwords
  - API tokens
  - OAuth
  - JWTs
  - Environment variables

---

## Security Concepts Introduced

- Protecting dangerous endpoints
- Validating user-provided credentials
- Limiting access to destructive actions
