# Lecture 1: Introduction to APIs

## What Is an API?

**API** stands for **Application Programming Interface**.

An API is:

- A **set of rules and protocols**
- That defines **how different software systems communicate**
- Acts as a **bridge** between programs that may be built differently

### Simple Analogy

- Program A speaks _Chinese_
- Program B speaks _Japanese_
- An **API is the translator/interface** that allows them to work together

---

## Why APIs Matter

Modern software runs the world:

- Books → Amazon
- TV → Netflix
- Devices → Phones, computers, even fridges

With so much software:

- **Communication between systems is essential**
- APIs enable this communication in a standardized way

---

## Core Purpose of an API

- Allows software to **request data or actions**
- Hides internal implementation details
- Clearly defines:
  - What you can request
  - How to request it
  - What response you’ll receive

---

## Real-World API Examples

### 1. Weather API (Data Retrieval)

**Use case:** Diary website that shows the weather for each day.

- A company (e.g., OpenWeather) stores weather data
- You don’t know:
  - Their database structure
  - Their backend language
- Their **API tells you how to interact** with their service

**Example flow:**

- Send latitude & longitude
- Receive structured data:
  - Temperature (°C)
  - Weather type (e.g., cloudy)
  - Weather icon

➡️ Typically uses a **GET request**

---

### 2. Newsletter Signup (Data Submission)

**Use case:** Collect emails and store them in Mailchimp.

- User submits email on your website
- You send the data to Mailchimp via their API

**API responsibilities:**

- Defines how to structure a **POST request**
- Tells you:
  - What data to send
  - Possible success responses
  - Possible error responses

➡️ Uses **POST requests** to send data

---

### 3. IoT / Hardware API (Actions)

**Use case:** Watering a plant by tweeting at it 🌱

- Tweet triggers a request
- Hardware listens to an endpoint like `/water`
- Device responds by watering the plant

**API can return:**

- Amount of water released
- Soil moisture level

➡️ APIs can control **physical devices**, not just software

---

## What All APIs Have in Common

- They are an **interface between systems**
- They define:
  - Rules
  - Protocols
  - Expected requests and responses
- They allow systems to interact **without knowing internal details**

---

## Types of APIs (Architectural Styles)

Common API styles:

- REST
- GraphQL
- SOAP
- gRPC

These are **architectural styles**, similar to:

- Different styles of building houses
- Each style follows different design rules

### Learning Approach

- **Just-in-time learning**
- Learn the API style you need _when you need it_

---

## REST APIs (Most Important for Web Development)

### What Is a REST API?

- An API that follows **REST principles**
- Uses the **HTTP protocol**

### Common HTTP Methods

You already know these:

- `GET` – Retrieve data
- `POST` – Create data
- `PUT` – Replace data
- `PATCH` – Update data
- `DELETE` – Remove data

➡️ Knowing HTTP means you already understand the basics of REST

---

## Using APIs Without a Website: Postman

**Postman** is a tool that lets you:

- Send HTTP requests
- Test APIs
- View responses
- Avoid building a frontend or backend just for testing

## Practical Example: “Where the ISS At?” API

### Goal

- Find the **live location of the International Space Station**
- Use latitude & longitude in Google Maps

### Steps Overview

1. Read the API documentation (like a menu)
2. Identify the correct endpoint
3. Use a `GET` request
4. Receive latitude & longitude
5. Paste coordinates into Google Maps
