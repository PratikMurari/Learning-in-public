## APIs Recap: Private vs Public

### Private APIs

- Used internally between your **frontend and backend**
- Not documented for public use
- Example:
  - Frontend makes a `GET` request to your server
  - Server responds with data or a webpage

> If someone figures out how your server works and accesses it directly, they are technically using your private API.

---

### Public APIs

- Designed for **external use**
- Fully documented
- Expose specific functionality or data
- Allow your server to communicate with **other servers**

This module focuses on **using public APIs**.

---

## Example API: Bored API

- Name: **Bored API**
- Purpose: Provides activities to do when you’re bored
- Documentation URL:

```
https://bored-api.appbrewery.com/
```

The API includes data such as:

- Activity description
- Type of activity
- Number of participants
- Cost (free or paid)
- Links (if available)

---

## API Endpoints

### What Is an Endpoint?

An **endpoint** is:

- A specific route on the API server
- Appended to the **base URL**
- Used for a specific purpose

**Structure:**

```

Base URL + /endpoint

```

### Examples (Bored API)

- `/random` → Get a random activity
- `/filter` → Filter activities by criteria
- `/activity` → Get a specific activity

Endpoints are:

- Fixed
- Defined in API documentation
- Used to access different resources or actions

---

## Making a GET Request (Random Activity)

### Steps

1. Read the API documentation
2. Identify the endpoint (`/random`)
3. Open Postman
4. Create a new **GET** request
5. Paste the full URL:

```
https://bored-api.appbrewery.com/random
```

6. Click **Send**

### Response Includes

- Activity description
- Activity type
- Number of participants
- Price (free or not)
- Optional link

---

## Rate Limiting

Most public APIs include protections against abuse.

For the Bored API:

- **100 requests per 15 minutes**
- If exceeded:
- You will receive a “too many requests” response
- You must wait before trying again

## Query Parameters

### What Are Query Parameters?

Query parameters:

- Provide **additional information** to an API request
- Are appended to the URL
- Used for:
- Filtering
- Searching
- Sorting

### Syntax

- Start with a **question mark (`?`)**
- Use **key=value** pairs
- Multiple queries are separated by **ampersands (`&`)**

**Example:**

```
/filter?type=social&participants=2
```

---

### Query Parameter Rules

- First query starts with `?`
- Every additional query starts with `&`
- Format:

```
?key=value&key2=value2&key3=value3
```

---

## Filtering Activities (Query Parameters)

### Goal

Find activities that are:

- Type: `social`
- Participants: `2`

### Endpoint

```
/filter
```

### Full Request Example

```
https://bored-api.appbrewery.com/filter?type=social&participants=2
```

### Notes

- Query parameters are **optional**
- API documentation must be followed exactly
- Parameter names must match documentation (e.g. `participants`, not `participant`)

---

## Path Parameters

### What Are Path Parameters?

Path parameters:

- Are part of the URL path itself
- Identify a **specific resource**
- Often represent:
  - IDs
  - Keys
  - Usernames

### Key Difference

- **Query Parameters** → filtering/searching
- **Path Parameters** → identifying a specific resource

---

## Using Path Parameters (Specific Activity)

Each activity has a **unique key**.

### Example Key

```
5914292
```

### Endpoint

```
/activity
```

### Full Request Structure

```
https://bored-api.appbrewery.com/activity/5914292
```

### Result

- API searches for the activity with that key
- Returns the complete activity object

## Summary of Request Structures

### Endpoint

```
/random
```

### Query Parameters

```
/filter?type=social&participants=2
```

### Path Parameters

```
/activity/{key}
```

## Key Takeaways

- **Endpoints** define what action or resource you’re accessing
- **Query Parameters** refine or filter results
- **Path Parameters** identify a single, specific resource
- Always consult the **API documentation**
- Use **Postman** to test requests quickly
