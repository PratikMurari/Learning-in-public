# Extending in Sass (`@extend`)

`@extend` lets one selector **inherit** the styles of another.  
It’s useful when two elements share most of the same styling and you want to avoid copy-pasting code.

Think of it as saying:

> “This selector should behave like that selector, plus any extra styles I add.”

---

## ⭐ Why Use `@extend`?

Without Sass, you might duplicate styles:

```scss
header {
  background: lightblue;
  color: #333;
  height: 100vh;
}

.contact {
  background: lightblue;
  color: #333;
  height: 100vh;
}
```

This is repetitive and harder to maintain.

With `@extend`, you reuse everything:

```scss
.contact {
  @extend header;
}
```

Now `.contact` inherits all of `header`’s styles.

---

## 🧩 Basic Syntax

```scss
.target {
  @extend selector;
}
```

Example:

```scss
.alert {
  background: orange;
  color: white;
}

.warning {
  @extend .alert;
  border: 2px solid red;
}
```

---

## 🎯 Example From the Video

```scss
header {
  height: 100vh;
  background: lightblue;
  color: $text-color;
}
```

Later:

```scss
.contact {
  @extend header;
  background: pink; // overrides inherited rules
}
```

### What happens?

- `.contact` receives all of `header`’s styles
- But since CSS is top-to-bottom, the pink background **overrides** the inherited one

---

## 📌 How `@extend` Compiles in CSS

This Sass:

```scss
header {
  background: lightblue;
}

.contact {
  @extend header;
  background: pink;
}
```

Becomes:

```css
header,
.contact {
  background: lightblue;
}

.contact {
  background: pink;
}
```

Notice:

- Sass merges selectors (`header, .contact`)
- Then applies overrides individually

---

## ⚠️ When NOT to use `@extend`

Although powerful, `@extend` can introduce issues when misused:

| Issue                       | Why                                                   |
| --------------------------- | ----------------------------------------------------- |
| Unexpected selector merging | Sass may combine selectors in surprising ways         |
| Harder to debug             | CSS output becomes less linear                        |
| Inheritance is “global”     | Mixing too many extends creates large selector chains |

For many developers, **mixins are safer** because they’re more explicit.

---

## ✔️ Use `@extend` sparingly, such as for:

- Shared “base classes”
- Repeating component patterns
- Simple inheritance
- Avoiding duplicated large style blocks

---

## ✔️ Summary

`@extend` helps you:

- Reuse styles without repeating code
- Inherit a selector’s full style set
- Keep CSS shorter and cleaner
- Override inherited values easily

But use it wisely, mixins are often more flexible.
