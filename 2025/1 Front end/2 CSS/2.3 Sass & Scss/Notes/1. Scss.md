# Why SCSS

- We'll use SCSS in these notes because it's a superset of CSS that keeps the same brace-and-semicolon syntax, so it looks exactly like CSS and is super easy for beginners to pick up.

- SCSS is a superset of CSS, which means any valid CSS is valid SCSS! This makes it the closest to CSS in look and feel.

- Beginners coming from CSS often find SCSS easier
  because it preserves curly braces `{}` and semicolons `;` while adding awesome Sass features like variables, nesting, mixins, and @extend.

- Sass (the indented syntax) removes both curly brackets AND semicolons, and uses whitespace-based indentation instead—kind of like Python! It also has different keywords (like `=` for mixins instead of `@mixin`).

- Sass could be more confusing for beginners because you have to be careful with indentation and spacing, plus the syntax looks quite different from the CSS you already know, so let's stick with SCSS to keep things simple! 🤗

**Quick tip**: Both SCSS and Sass compile to the same CSS and have the exact same features, it's just different syntax. Most developers today prefer SCSS because it's CSS-compatible.
